# コミットポリシー（workflow-commit.md）

このファイルは「コミット単位の分割」と「コミットメッセージ規約」を定義する。
タスク・会話レベルの分割は `base.claude.md` 5節、TDD サイクルは `workflow-tdd.md` を参照。

---

## 1. 作業の分割ルール

**このファイルの「分割」はコミット単位を指す。タスク粒度の分割は `base.claude.md` に従う。**

- 新しい依頼を受けたら、最初に「今回の変更をどのサブタスクに分けるか」を箇条書きで提示する。
  - 例:
    - [ ] 保存成功時の toast を実装
    - [ ] toast 表示のテストを追加・更新
    - [ ] 画面レイアウトの調整・フィールドの編集 UI 実装
- サブタスクは1つずつ順番に完了させ、完了タイミングで**そのサブタスクだけを含むコミット**を作成する。
  - Why: 大きな変更を一度にコミットすると、レビュー・問題切り分け・revert が困難になるため。

---

## 2. コミットの分け方

1 つのコミットに含める変更は、**1 種類の目的に絞る**。以下は別コミットに分ける：

- UI の変更 / レイアウト調整
- ビジネスロジックの追加・修正
- テストの追加・更新
- リファクタリング（振る舞いを変えないコード整理）

Why: 目的が混在すると、コミットの責務が不明瞭になり、後から特定の意図だけを revert・cherry-pick できなくなるため。

### 具体例: アラート詳細画面の改善

「保存時に toast を出して、テストを書いて、画面も少し直す」ケースでの分割：

| # | 内容 | メッセージ例 |
|---|---|---|
| 1 | 保存成功時の toast 実装（UI コンポーネント / hooks 含む） | `feat(alerts): show toast on successful alert update` |
| 2 | toast 表示のテスト追加・更新（テストヘルパー微調整含む） | `test(alerts): add tests for alert update toast` |
| 3 | 編集フィールド追加・レイアウト変更・フォーム周り変更 | `feat(alerts): make alert detail fields editable` |
| 4 (任意) | コンポーネント分割・命名変更等の振る舞い不変リファクタ | `refactor(alerts): extract alert detail form component` |

---

## 3. コミットメッセージ

- **Conventional Commits** に近い形式を使う。
- 接頭辞: `feat:` 新機能、`fix:` バグ修正、`refactor:` 振る舞い不変リファクタ、`test:` テスト追加・修正
- スコープ（対象機能・ドメイン）を括弧で指定する。
  - 例: `feat(alerts): show toast on successful alert update` / `test(auth): add tests for session fetch error`
- `wip` のような意味の曖昧なメッセージは使わない。
  - Why: 後から git log を辿る際、接頭辞とスコープで grep・絞り込みできるようにするため。

---

## 4. TDD との関係

- 1 サブタスク = 1 TDD サイクル（レッド → グリーン → リファクタ） = 1 コミット が基本。
- テストを独立コミット化したい場合は、サブタスク段階で切り出す（2節の Commit 2 参照）。
- Why: サイクル途中（レッドだけ・グリーンだけ）のコミットは履歴に壊れた状態を残し、bisect とレビューが困難になるため。
